# Agent Note: tool-ci（CI 质量门禁工具）

Status: implemented

[English](2026-08-24-tool-ci.md) | 中文

## 问题

每个 CI 门此前都是一次独立的 bash 调用，模型只能从交错的输出中自行推断总体结论。多门检查需要单一结构化结论、首个失败即停止的策略以及有界的输出，同时不能把 shell 执行器的职责（沙箱、超时、取消）挪进工具。

## 决策

新增 `@deepseek-ai/dsh-tool-ci`：构建在 `ctx.shell` 能力缝上的模型可用 `ci_run` 工具。每个门是一条 shell 命令字符串；工具按顺序执行，并限制每门捕获的 stdout/stderr 尾部长度。非零退出、终止信号、执行器超时或中止都会把该门标记为失败；默认在首个失败处停止序列，其余门标记为跳过。规范值是程序化 API；Native 渲染器把它折叠成 markdown 摘要，终端卡片（presentCall/presentResult）为 UI 携带合并输出。配置：`timeoutMs`（每门预算）、`maxOutputChars`（输出上限）、`stopOnFailure`（默认策略）。

tool-ci 注册在基础 bundle（`packages/bundle/base/cordis.patch.yml`，面向 CLI profile）与标准 Agent 预设（`apps/cli/config/agent-presets/standard/agent.cordis.yml`，面向 Web 面）中，并在 `packages/bundle/base/package.json` 补充对应的包依赖。

## 备选方案

**每门一次 bash 调用、由模型推断结论。** 否决：交错输出既给不了模型结构化结论，也没有停止策略；一长串无关失败会淹没首个失败的门。

**经新执行器而非 `ctx.shell` 运行门禁。** 否决：沙箱、超时与取消仍是 shell 执行器的职责；按工具复制它们会劈开执行点。

## 后果

模型看到的是首个失败的门，而不是一串失败级联，且每条门记录都携带退出码、信号、超时/中止事实、耗时与有界的输出尾部。shell 执行器关切留在工具之外；缺少 `ctx.shell` 的组合无法加载它，每次 `ci_run` 调用都是有界的前台序列。
