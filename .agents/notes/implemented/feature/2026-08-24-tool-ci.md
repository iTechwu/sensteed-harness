# Agent Note: tool-ci (CI quality-gate tool)

Status: implemented

English | [中文](2026-08-24-tool-ci.zh.md)

## Problem

Each CI gate was previously a separate bash call, and the model had to infer the overall verdict from interleaved output. Multi-gate checks need one structured verdict, a first-failure stopping policy, and bounded output, without moving shell executor responsibilities (sandboxing, timeouts, cancellation) into the tool.

## Decision

Add `@deepseek-ai/dsh-tool-ci`, a model-facing `ci_run` tool over the `ctx.shell` capability seam. Each gate is a shell command string; the tool runs them in order, capping the captured stdout/stderr tail per gate. A non-zero exit, a terminating signal, an executor timeout, or an abort marks the gate failed; by default the sequence stops at the first failure and marks the rest skipped. The canonical value is the programmatic API; the Native renderer folds it into a markdown summary, and the terminal card (presentCall/presentResult) carries the combined output for the UI. Config: `timeoutMs` (per-gate budget), `maxOutputChars` (output cap), `stopOnFailure` (default policy).

tool-ci is registered in the base bundle (`packages/bundle/base/cordis.patch.yml`) for CLI profiles and in the standard agent preset (`apps/cli/config/agent-presets/standard/agent.cordis.yml`) for the Web surface, plus the corresponding package dependency in `packages/bundle/base/package.json`.

## Alternatives considered

**One bash call per gate with model-side verdict inference.** Rejected: interleaved output gives the model no structured verdict and no stopping policy, and long cascades of unrelated failures bury the first failing gate.

**Running gates through a new executor instead of `ctx.shell`.** Rejected: sandboxing, timeouts, and cancellation stay the shell executor responsibility; duplicating them per tool would fork the enforcement point.

## Consequences

The model sees the first failing gate rather than a cascade, and every gate record carries exit code, signal, timeout/abort facts, duration, and a bounded output tail. Shell executor concerns remain outside the tool; a composition without `ctx.shell` cannot load it, and each `ci_run` call stays a bounded foreground sequence.
