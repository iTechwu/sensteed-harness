# Agent Note: SDK 会话线上控制

Status: implemented

[English](2026-08-24-sdk-session-wire-control.md) | 中文

## 问题

SDK 运行时需要对会话进行中的工作的线上级控制：取消运行中的 Agent、从持久化恢复，以及变更持久化审批策略。这三者此前都藏在某个内部工厂或事件之后，另造一套并行 JSON-RPC 语义会把持久化、审批策略与 Agent 生命周期的所有权劈成两半。线上契约还需要划清界线：会话创建者可以播种什么（一个环境覆盖层），以及什么必须留在进程配置之外。

## 决策

SDK 运行时把取消、基于持久化的恢复和持久化审批策略变更暴露为会话自有的 JSON-RPC 请求。`session/cancel` 中止运行中的 Agent，不关闭子进程。`session/resume` 委托给既有的 `AgentRegistry.resume` 工厂，持久化所有权与装配回滚保持在同一实现内。`session/approval-policy` 追加既有的 `approval/policy` 事件，而不是发明第二个策略存储。

首条 prompt 可以携带每会话的环境覆盖层，但它在会话创建后不可变，且只允许 `DEEPSEEK_BASE_URL`。凭据、解释器搜索路径、动态加载器变量与任意的进程环境修改都留在线上契约之外。当运行时尚未持有全局 adapter 时，一个作用域化的 DeepSeek 插件消费该覆盖层；全局 adapter 与覆盖层并存会被拒绝，而不是静默忽略所请求的端点。

## 备选方案

**经线上逐会话关闭。** 否决：取消是工作控制操作，而 `shutdown` 仍是进程生命周期拆除；按会话暴露关闭会混淆两者并使子进程所有权复杂化。

**经线上寻址的第二个审批策略存储。** 否决：追加既有的 `approval/policy` 事件保住了单一持久化策略历史；独立的存储需要对答复方决策另做一套对账。

## 后果

TypeScript SDK 两层与协议类型映射暴露相同的方法。审批*策略*受线上控制；单次审批决定仍是答复方的能力，没有请求身份与持久化审计配对时不会被合成。每会话关闭是有意缺席的：取消是工作控制操作，而 `shutdown` 仍是进程生命周期拆除。
